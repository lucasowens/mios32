## 1. CHOKE — cut the ring at the slice edge (CC 0xA9)

Verified against source: a par Length is `value+1` clamped to **96 ticks = one
step** (seq_layer.c GetEvents) — a note can never outring its own step via
length. The only per-step cross-edge tail is the **GLIDE trg bit** (ties step
→ next step; chains ring across the new cut points after a permute, blurring
the chop). Track-mode SUSTAIN is an emission-time track flag — out of render
reach, rides on top like Echo (accepted).

- `SEQ_CC_SLICE_CHOKE = 0xA9`, tcc `slice_choke`, dial "Chok", 0..127,
  0 = off = true pass-through.
- **Per-slice thermometer** (the REPT/REV idiom): slices hash-ranked in a new
  zone `GRIP_ZONE_SLICE_CHOKE 0x64`; dial = how many slices get choked.
  A choked slice = clear the GLIDE bit at its **final output step** (per trg
  instrument, in the render trg buffer, after the permute). Applies to painted
  slices too — choke is articulation, not order (REPT/REV skip painted because
  painted promises exact *content*; a tail cut doesn't break that promise).
- Joins the all-axes-0 early-out in `slice_render_apply` (strength / rept /
  rev / choke all 0 = pass-through). CHOKE alone (strength 0) is legitimate:
  it tightens the ORIGINAL loop at grid edges — a gate-tightener with no
  reorder.
- Only meaningful where a glide trg layer is assigned (melodic tracks);
  drum tracks: no glide assignment → no-op, dial still sweeps clean.

## 2. MOTION — per-bar re-roll (CC 0xAA)

The act-1 "alive" variant: re-roll the seeded fill every N bars. Only the MAP
hash folds seed (act-1 grammar) → the engage/stutter/reverse skeleton AND all
painted slices stay put while the fill re-rolls — motion animates the Seed
dial, nothing else.

- `SEQ_CC_SLICE_MOTION = 0xAA`, tcc `slice_motion`, dial "Motn", 0 = off
  (frozen = act 1); 1..4 = every 8/4/2/1 bars — a 5-detent rate selector
  (the Grid idiom, one click per rate). *Refined 2026-07-17 after first
  hands-on: the original 0..127 zone-quarters encoding needed 32 clicks per
  zone and read as "stuck at 8bar".*
- Bar index = `t->robotize_measure_ctr` (verified: increments for EVERY track
  at each global-measure ref_step==0 boundary, seq_core.c ~5590; resets at
  transport start → deterministic per run). `epoch = ctr / N`;
  `seed_eff = seed ? 1 + ((seed-1) + epoch*53) % 127 : 0` — seed 0 stays
  identity (MOTION is a modifier on the seed axis, not a seed source), and
  motion 0 keeps `seed_eff == seed` exactly (act-1 renders byte-identical).
- **Boundary render lands ON the One:** `SEQ_CORE_RenderTracks` runs at the
  TOP of the tick (5488) — before the ref_step==0 hook — so a dirty flag set
  at the boundary would render one tick late and smear the downbeat. Fix =
  the existing idiom (TensionResolveBoundary spirit): inside the ref_step==0
  block, for each track with slot armed && motion && seed && (ctr % N)==0:
  set dirty + call `SEQ_CORE_RenderTrack(track)` synchronously. Same cost
  class as one dial-write render (the sweep fence already forces quiet full
  renders per CC write).
- Mid-epoch renders (dial moves) rebuild the SAME map (ctr/N constant within
  the epoch) — no drift. While STOPPED the counter is static → chop freezes
  at the last epoch (edit-flush renders stay deterministic).

## 3. Live slice-jump pads (PROC_FACE_SLICE_JUMP, face1)

Performance gesture: pads jump the playhead to a slice. NO new playhead
machinery needed — verified: `SEQ_CORE_SetTrkPos(track, step, 0)` while
playing latches `manual_step` + `MANUAL_STEP_REQ`, consumed at the next step
advance (seq_core.c ~5793) = a **step-quantized jump**; while stopped it sets
the step directly. Exactly the retrigger feel wanted.

- Slic row plane 1: dials occupy GP1-7 (Grid/Seed/Str/Rept/Rev/Chok/Motn),
  **GP9-16 = jump pads for slices 1-8** — the PROC_FACE_TENSION_ZONES shape
  (`pc >= 8`), new `PROC_FACE_SLICE_JUMP` as the row's face1 (row has no
  bespoke face yet, and face1 is the established slot for single-plane rows).
- Pad n → `SEQ_CORE_SetTrkPos(visible_track, (pc-8)*len, 0)`. Active iff
  `(grid & 0x07) != 0` (geometry defined; bypass bit irrelevant — the jump is
  playhead, not render). Pads past the track's slice count = ignored.
- 8 pads cover the typical material exactly (16 steps / 2-step grid = 8
  slices); longer loops jump within the first 8 slices — POC grain, extend
  only if the ear asks.
- LCD GP9-16 cells: slice numbers 1..min(S,8), a `>` marker on the currently
  playing slice (`t->step / len`), dashes past S.
- **Control-surface map entry required before ship** (grammar rule).
